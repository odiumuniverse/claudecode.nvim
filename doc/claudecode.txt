==============================================================================
INTRODUCTION                                                      *claudecode*

claudecode.nvim connects the Claude Code CLI to Neovim over the IDE protocol.
Claude opens files, reads your selection and diagnostics, and shows its edits
as diffs. Two features come on top:

    Hunk review   Keep or revert each change Claude makes, as Cursor does,
                  instead of accepting or rejecting a whole file.
    Zen mode      Run Claude full screen inside Neovim and flip to the code
                  with one key.

Claude runs as the unmodified `claude` binary, so you sign in with your own
Claude subscription.

This file documents hunk review and zen, and the commands kept from
coder/claudecode.nvim (upstream), which has no Vim help. The IDE connection
and its options are in the upstream README:
https://github.com/coder/claudecode.nvim#readme

The reasons behind the design are in docs/DESIGN.md.

==============================================================================
REQUIREMENTS                                         *claudecode-requirements*

- Neovim 0.11 or newer. Older versions skip review and zen, so the plugin
  behaves as upstream and nothing in this file exists.
- Claude started from Neovim: `:ClaudeCode`, |:ClaudeCodeZen| or `cz`. Review
  after write rides on hooks attached at launch (|claudecode-review-state|).
- `git`, to review the edits Claude makes through Bash.
- For zen, the Claude terminal inside Neovim: `terminal.provider` set to
  "snacks", "native" or "auto".

==============================================================================
MODES                                                       *claudecode-modes*

Claude's permission mode picks the review. Switch it in Claude with
shift+tab; the next edit follows the new mode, and an edit already under way
ends the way it began.

Manual (`default`)
    Claude waits for you. The proposal opens in Neovim, and you keep or
    revert each hunk before Claude writes the file
    (|claudecode-review-before-write|).

Auto, `bypassPermissions` and `dontAsk`
    Claude does not ask about edits. What it writes waits for you as hunks
    in the file (|claudecode-review|).

Accept edits (`acceptEdits`)
    Claude writes, and the plugin keeps the edit without review. Hunks left
    from earlier edits stay; an edit that touches one of them joins it. So
    does an edit you allow with "Yes, and switch to accept edits" at
    Claude's prompt.

Plan
    No review. Claude writes only its plan file here.

In Manual mode the plugin asks about every edit, even one your Claude
settings allow without asking (`permissions.allow`): its PreToolUse hook
answers "ask" for Edit, Write, MultiEdit and NotebookEdit. Bash keeps your
own permission rules, and its edits come up as hunks after the call.

To start Claude in Manual mode: >vim
    :ClaudeCode --permission-mode manual
<
The LazyVim spec maps this to `<leader>am`. Without the flag Claude starts in
the mode from your Claude settings (`permissions.defaultMode`). The flag
counts only when Claude starts: while Claude runs, `:ClaudeCode` just shows
or hides it. Switch a running session with shift+tab.

The modes need the hooks, so they work only for Claude started from Neovim
(|claudecode-review-state|). A Claude you start yourself has no hooks and asks
only when your Claude settings say so. With `review.before_write = false` the
hooks never ask either: Claude asks only as your settings say, in upstream's
diff views.

==============================================================================
HUNK REVIEW                                                *claudecode-review*

In auto mode Claude edits your files right away, as it does in a terminal.
The plugin then draws what changed on top of the code:

- deleted lines appear in red above the change, as virtual lines that are
  not part of the file;
- added lines get a green background;
- inside a changed line, only the changed words stand out
  (|claudecode-review.word_diff|);
- the hunk under the cursor shows a hint at the end of its first line, with
  which hunk of how many in this file it is: "2/5  cs keep · cx revert"
  (|claudecode-review.hint|);
- the statusline can show how many files wait (|claudecode-review-status|).

A hunk is a run of changed lines. The plugin does not use the sign column.

A buffer is under review while its file holds hunks you have not decided on.
Hunks are measured against the file as it was before Claude's first edit that
you have not reviewed. They pile up across Claude's turns until you keep or
revert them.

------------------------------------------------------------------------------
KEYS                                                  *claudecode-review-keys*

The keys exist only in buffers under review. They are buffer-local normal
mode mappings. A mapping the buffer already had on the same key comes back
when the review ends. Set a key to `false` to leave it unmapped
(|claudecode-review.keymaps|).

    Key   Option                      Action ~
    cs    review.keymaps.keep         Keep the hunk under the cursor
    cx    review.keymaps.revert       Revert it; the file is written at once
    cS    review.keymaps.keep_all     Keep every hunk in the buffer
    cX    review.keymaps.revert_all   Revert every hunk in the buffer
    ]k    review.keymaps.next         Next hunk; takes a count
    [k    review.keymaps.prev         Previous hunk; takes a count
    ]K    review.keymaps.last         Last hunk
    [K    review.keymaps.first        First hunk
    cr    review.keymaps.note         Note for Claude on this line

In visual mode `<leader>an` (`review.keymaps.note_range`) takes a note on the
selected lines. `cR` sends every note to Claude from any buffer
(|claudecode-notes|).

Keeping makes Claude's text the new base. The buffer and the file stay as
they are.

Reverting brings the base text back into the buffer and writes the file at
once, together with your unsaved edits in that buffer. One undo step takes
the revert back. If the file changed on disk since the buffer last read or
wrote it, because Claude wrote again, nothing is reverted. The plugin warns,
reloads the buffer when it can, and you revert again.

After `cs` or `cx` the cursor moves on to the next hunk, or to the first one
after the last. Once the file has no hunk left, it stays; with `advance =
"file"` the next file waiting for review opens (|claudecode-review.advance|).

Inside a file `]k` and `[k` never wrap, and a count past the last hunk goes
as far as it can. With no hunk left that way, `]k` opens the next file
waiting for review at its first hunk and `[k` the previous one at its last
hunk; the list goes in path order and wraps around
(|claudecode-review.cross_files|). They set the jump mark, so <C-o> goes
back. In a file that is not under review, `]k` and `[k` open the next or
previous file waiting for review, and say "nothing waits for review" when
none does; a global mapping of your own on these keys stays yours there. `cs` and `cx` outside a hunk say "no hunk here".

Why `c`: Neovim waits for a motion after `c` in any case, and `s`, `x`, `S`
and `X` are no motions, so these keys delay nothing. A key such as `ko` would
make every `k` wait for 'timeoutlen' in a buffer under review. In a buffer
under review `c` itself waits for the next key without a timeout, so a pause
between `c` and `s` still keeps the hunk instead of running Flash. Any other
key after `c` changes text as always: `cw`, `ciw`, `cc`, `2cw`, `"acw`.

------------------------------------------------------------------------------
FILES WAITING FOR REVIEW                             *claudecode-review-files*

|:ClaudeCodeReview| and `review.files_keymap` (`<leader>ak`) open a list of
the files that have hunks you have not decided on, or notes not sent to
Claude yet (|claudecode-notes|). Each entry shows the path, "(new)" for a
file Claude created, the lines added and removed, and how many hunks and
notes wait, in columns:
>
    lua/cart.lua      +12 -3  3 hunks · 1 note
    lua/receipt.lua    +4 -4  1 hunk
    lua/tax.lua               1 note
<
For each file you can:

    open          Go to the file, at its first hunk, or at its first note
                  when no hunk is left.
    keep all      Keep every hunk in the file.
    revert all    Revert every hunk in the file and tell Claude.

The list uses snacks.picker, fzf-lua or `vim.ui.select`, whichever
`review.picker` picks (|claudecode-review.picker|). In snacks.picker and
fzf-lua, <CR> opens the file, <A-o> keeps all of it and <A-x> reverts all of
it. `vim.ui.select` asks which of the three to do. When no file waits, the
command says "nothing waits for review".

                                                 *claudecode-review-status*
For a statusline, `require("claudecode.review.controller").status()` gives
"review: 2 files", "review: 1 file", or "" when nothing waits, so the
component disappears. The LazyVim spec in the repository adds it to lualine;
by hand:
>lua
    { function() return require("claudecode.review.controller").status() end,
      color = "ClaudeCodeReviewCount" }
<

------------------------------------------------------------------------------
WHAT GETS REVIEWED                                   *claudecode-review-scope*

Unless Claude is in accept-edits or plan mode (|claudecode-modes|), these
are reviewed:

- Edit, Write, MultiEdit and NotebookEdit: every call. In Manual mode you see
  the proposal first (|claudecode-review-before-write|).
- Bash in a git repository: every file it changed, created or deleted. The
  plugin snapshots the work tree before the call with `git stash create` on
  a copy of the index, so it neither touches your stash list nor takes your
  `index.lock`. Files that git checks out with CRLF endings (`eol=crlf`,
  `core.autocrlf`) keep them through review and revert.
- Bash in a project whose folder is not a git repository but holds several:
  every repository one level below that folder, up to 32, so `cd api && make
  fmt` from the folder or `cd ../web` from a neighbor is reviewed too. The
  plugin snapshots them all at once; with 22 repositories that takes about
  0.3 s per Bash call.
- A Bash command that moves HEAD (`git switch`, `pull`, `rebase`, `reset`):
  only your uncommitted work it threw away, and the edits Claude made after
  the checkout, compared with the new HEAD. The files git simply checked out
  are not Claude's edits and stay out of review.
- An untracked file Bash rewrote or deleted. Git keeps no copy of it, so
  the plugin copies untracked files up to 2 MB before each Bash call, 200
  files and 20 MB at most; on APFS a copy is a clone and costs next to
  nothing. Past those limits such a file is reviewed only when it is open in
  Neovim and unmodified.
- Files outside the project as well, such as Claude's memory under
  `~/.claude/`: review follows Claude's edit tools wherever they write.

Not reviewed:

- binary files (a NUL byte in the first 8000 bytes) and files over 2 MB;
- new files Bash creates in paths that `.gitignore` covers;
- edits outside a Claude tool call: yours, `git pull`, other programs;
- Bash edits outside git repositories;
- an edit the same Bash call commits (`sed -i f && git commit -am …`): after
  the call `f` matches the new HEAD, as after a checkout.

If you refuse an edit and then create or change that file yourself, review
treats the file as yours.

------------------------------------------------------------------------------
YOUR EDITS                                           *claudecode-review-edits*

You can edit a buffer under review.

- An edit outside a hunk becomes part of the file and of the base. It does
  not become a hunk.
- An edit inside a hunk changes Claude's proposal. The hunk waits for `cs` or
  `cx`.
- After `cx`, `u` brings Claude's text back as your own edit: it joins the
  base and is no hunk.

When Claude writes a file, the PostToolUse hook tells Neovim which files
changed, and their open buffers reload. A buffer with unsaved edits does not
reload: the plugin warns you, and when the file has hunks waiting, review
starts once `:edit!` loads Claude's version.

------------------------------------------------------------------------------
NOTES FOR CLAUDE                                            *claudecode-notes*

Instead of reverting a change, ask Claude to rework it. Put the cursor on the
line in question and press `cr`, or select lines and press `<leader>an`. A box
opens right under that line and moves the code below out of its way, so even
a long hunk stays in sight; near the bottom of the window the window scrolls
to make room. Type what you want; the box grows up to 10 lines.

    <CR>      Save the note; with `notes.send = "enter"`, save and send
    <S-CR>    Save the note and send every note to Claude
    <C-s>     The same, for a terminal that sends Shift+Enter as Enter
    <Esc>     Close the box and drop what you typed

<C-j> starts a new line in the note. Back in Normal mode (`jk`, say) the box
stays open: <CR> saves there too, and <Esc> drops what you typed.

A saved note shows as one line under its last line, "▎ note: …", and moves
with the code around it. `cr` on a noted line opens the note again; save it
empty to delete it. Notes go to the state directory at once and survive a
restart of Neovim. A note on lines you revert with `cx` goes away: the text it
was about is gone.

A note counts as a decision on its hunk: after <CR> the cursor moves on to the
next hunk without a note, `cs` and `cx` move on past noted hunks too, and a
file whose hunks all have notes is done for `advance = "file"`.
`review.notes.advance = false` turns this off.

`<leader>an` in Normal mode (|claudecode-review.notes.list_keymap|) or
|:ClaudeCodeReviewNotes| lists every note, by file and line, before you send
them. The preview shows the code with the note under it. In snacks.picker
<CR> opens the note in its box to edit it, and the cursor stays on it after
you save; <A-d> deletes the note and <C-s> sends them all. fzf-lua takes the
same keys; `vim.ui.select` asks what to do.

`cR` (|claudecode-review.notes.send_keymap|) or |:ClaudeCodeReviewSend| sends
every note from every file in one message, from any buffer. The message lists
each place as file:line, the first lines of the code there and your note, and
asks Claude to rework them. It is typed into the Claude terminal in Neovim and
submitted; while Claude works, Claude Code queues it. Sent notes go away.
When Claude does not run in a Neovim terminal (the "external" and "none"
providers, or Claude not started yet), the notes stay and the message goes to
the clipboard.

In a proposal under review before write, `cr` does not keep a note for later:
Claude waits for your answer there, so it reverts the hunk with your reason
(|claudecode-review-before-write|).

------------------------------------------------------------------------------
REVERTS AND CLAUDE                                   *claudecode-review-notes*

Claude Code never tells the model that you rejected part of an edit. The
plugin adds a short note to Claude's context instead. The note arrives right
after Claude's next file edit or Bash call, or with your next message,
whichever comes first. Then the plugin forgets it.

The note names the file and line, shows Claude's text and the text that came
back, and asks Claude not to reapply the change unless you ask. It shows at
most 20 lines of each text and 8000 characters in all; changes past that limit
appear as a list of file names.

Every Claude session hears only about the files it edited. Two sessions in one
project share the state directory, and each file remembers which sessions
edited it. The note about a file that two sessions edited reaches both of
them. When a session gets no new note for 7 days, its saved notes are deleted
the next time any session asks for its own.

------------------------------------------------------------------------------
HOOKS AND STATE                                      *claudecode-review-state*

Every Claude session the plugin starts gets `claude --settings {file}` with
three hooks: PreToolUse and PostToolUse for Edit, Write, MultiEdit,
NotebookEdit and Bash, and UserPromptSubmit. Claude Code adds them to the
hooks you already have. It does not replace them. The plugin rewrites the
settings file at every launch:
`stdpath("state")/claudecode/hooks-settings-{id}.json`. The hooks in it run
this Neovim's binary on this copy of the plugin, and {id} comes from both
paths. A second Neovim with another binary or another copy of the plugin
writes its own file and never changes this one. `:checkhealth claudecode`
shows the name.

Each hook is a short `nvim --clean --headless -l` script. It copies the file
before the edit and tells Neovim about it, waiting half a second at most
for Neovim to take the message. A hook never blocks Claude: on any error it
writes to `hooks.log` and exits with 0, so at worst one edit escapes review.

If you start Claude yourself (`terminal.provider = "none"`), no hooks are
attached and review after write stays off. Review before write still works,
because it needs only the IDE connection.

The state lives in `stdpath("state")/claudecode/review/{hash}/`, where {hash}
is the SHA-256 of the project root. Only you can read the directory (mode
0700). It holds the text of each file before Claude's first unreviewed edit
and the sessions that edited it, the reverts not yet reported to Claude (one
file per session), and `hooks.log` with the last hook errors (kept under
64 KB). The directory empties as you decide on the hunks.

The root is the git repository around Neovim's working directory when Claude
starts, or the directory itself outside git. Start Neovim anywhere in the same
repository to get your reviews back.

==============================================================================
REVIEW BEFORE WRITE                           *claudecode-review-before-write*

In Manual mode Claude asks before each edit and sends its proposal over the
IDE connection. With `review.before_write` on, the plugin opens the proposal
in place of the file (|claudecode-review.before_write|). It draws the same
hunks and keys as review after write. The window shows "Claude proposes
changes to {file} · :w accepts the rest", and the buffer sets
`b:claudecode_proposal`.

You decide hunk by hunk. `cs` keeps a hunk of the proposal, `cx` reverts it
without touching the file on disk. When no hunk is left, the plugin answers
Claude: the text you kept goes to Claude, who writes it; if you reverted every
hunk, Claude gets a rejection.

`cr` reverts a hunk with a reason: a box opens under the line, and Enter
reverts the hunk and keeps what you typed. `<leader>an` on a selection does
the same for every hunk in it. The reason makes Claude rework the place at
once, in the same turn:

- If you kept other hunks, the reason goes with the note about your reverts
  (|claudecode-review-notes|), which asks Claude to rework the places that
  carry a reason.
- If you reverted every hunk, the plugin answers in Claude's own permission
  dialog in the Claude terminal: "No, and tell Claude what to do differently",
  with your reasons. The IDE connection cannot carry text with a rejection.
  Every key goes out only after the dialog on screen shows what that key
  needs. When it cannot be done (Claude runs outside Neovim, or the dialog
  looks different after an update of Claude Code), the proposal is rejected
  plainly and your reasons go to the clipboard, with a warning.

- `:w` in the proposal answers with what is there now. A buffer equal to the
  file is a rejection.
- `cS` takes the whole proposal, `cX` refuses all of it.
- If Claude closes the tab before you decide, the proposal is refused and the
  window goes back to your file.
- The text you accept becomes the base, so review after write does not show
  it again. A base that an earlier edit left, with hunks still waiting, stays
  as it is: you have not reviewed those hunks. Hunks you reverted reach
  Claude as a note
  (|claudecode-review-notes|); the CLI itself only says that you modified the
  proposed content.
- The proposal opens even when the file's buffer has unsaved edits.
- When zen is open, it steps aside for the proposal and comes back once you
  have decided (|claudecode-zen|).

Claude sends UTF-8. The plugin compares it with the file in the file's own
encoding, so a Latin-1 or UTF-16 file shows only what Claude changed. It reads
the encoding from the open buffer, or else from the byte order mark and
'fileencodings'. The protocol carries text only, so Claude writes UTF-8 after
you accept: a Latin-1 or UTF-16 file becomes UTF-8. A byte order mark stays.
The file's CRLF endings stay; the final newline follows Claude's text.

Set `review.before_write = false` to keep upstream's diff views instead: `:w`
in the proposed buffer accepts it, closing the buffer rejects it. Or set your
own `diff_opts.provider` (|claudecode-diff-provider|).

ZEN MODE                                                      *claudecode-zen*

|:ClaudeCodeZen| and `zen.keymap` (`<M-z>`) put Claude full screen in a tab of
its own, and bring you back to the code with Claude in its split. The key
works in normal mode and inside the Claude terminal; other terminals still
get the key (|claudecode-zen.keymap|).

- Zen hides the tabline, and keeps it hidden when a plugin such as
  bufferline.nvim shows it again. Leaving zen gives the tabline back as that
  plugin last set it.
- Above Claude, on the right, zen shows how many files wait for review in the
  words of the statusline (|claudecode-review-status|), and the key that
  lists them: "review: 2 files · <leader>ak". With no file waiting the bar is
  empty.
- Leaving zen returns you to the tab you entered from.
- If you switch to another tab while zen is open, the key takes you back into
  zen instead of building a second one.
- When Claude asks to approve an edit in Manual mode, zen steps aside for the
  proposal and comes back once you have decided
  (|claudecode-review-before-write|).
- When the Claude process ends, zen closes.

                                                           *claudecode-zen-cz*
`bin/cz` opens Neovim straight into zen. Put it on your PATH, then:
>sh
    ln -s ~/.local/share/nvim/lazy/claudecode.nvim/bin/cz ~/.local/bin/cz
    cz            # new session
    cz --resume   # pick a session to resume
<
Leaving zen after `cz` builds a tab for the code, since there was none.

Zen needs Claude inside Neovim. With `terminal.provider` set to "external" or
"none", it warns about that.

==============================================================================
ACCOUNTS (CSWAP)                                           *claudecode-cswap*

`:ClaudeCode run` runs Claude as one of your accounts in cswap
(claude-swap, https://github.com/realiti4/claude-swap), a switcher for
several Claude accounts:
>vim
    :ClaudeCode run 1             " account 1
    :ClaudeCode run work          " an alias, or the account's email
    :ClaudeCode run 1 --resume    " Claude's own arguments follow the account
    :ClaudeCode run               " the account `cswap map` gives this
                                  " directory, or your default login
<
- The account sticks. Every later launch from this Neovim runs it: the
  toggle, focus, zen and `--resume` too, until the next `:ClaudeCode run`.
- A Claude that already runs is stopped and replaced, without asking; its
  conversation ends. cswap keeps the history of each account apart.
- The plugin checks the account against `cswap list --json` before it stops
  anything, so a mistyped account leaves the running Claude alone.
- <Tab> completes the account numbers and aliases.
- When zen is open, the new Claude opens in zen.
- The plugin runs `cswap run {account} -- {args}`. cswap hands everything
  after `--` to Claude, the review hooks' `--settings` included.
- Each account has a profile of its own, so Claude asks once per account
  whether you trust the project folder.

|claudecode-cswap.cmd| names the cswap executable.

==============================================================================
COMMANDS                                                 *claudecode-commands*

Five commands come from upstream:

:ClaudeCode [{args}]    Toggle the Claude terminal. {args} go to `claude`,
                        as in `:ClaudeCode --resume` or `--model`.
:ClaudeCodeFocus        Focus the Claude terminal, or hide it when it has
                        focus.
:ClaudeCodeSend         Send the selection to Claude as context.
:ClaudeCodeAdd {path}   Add a file or directory to Claude's context.
:ClaudeCodeTreeAdd      Add the file under the cursor in nvim-tree,
                        neo-tree, oil or mini.files.

Upstream's other commands are gone: the review replaces them, or the plugin
does their work on its own. In a proposal `cS` takes it all, `cX` refuses
it and `:w` answers with what is there (`:ClaudeCodeDiffAccept`,
`:ClaudeCodeDiffDeny`, `:ClaudeCodeCloseAllDiffs`). `:ClaudeCode` toggles
(`:ClaudeCodeOpen`, `:ClaudeCodeClose`). The server starts with the plugin,
and `:checkhealth claudecode` shows its state (`:ClaudeCodeStart`,
`:ClaudeCodeStop`, `:ClaudeCodeStatus`). `:ClaudeCode --model` or Claude's
`/model` picks the model (`:ClaudeCodeSelectModel`), and notes send text to
Claude (`:ClaudeCodeSendText`).

Review and zen add four commands, and `:ClaudeCode` learns `run`.

                                                           *:ClaudeCodeReview*
:ClaudeCodeReview       Open the list of files with hunks you have not
                        decided on (|claudecode-review-files|). Defined when
                        `review.enabled` is true.

                                                      *:ClaudeCodeReviewNotes*
:ClaudeCodeReviewNotes  List the notes not sent to Claude yet: open one to
                        edit it, delete one, or send them all
                        (|claudecode-notes|), as `<leader>an` does.

                                                       *:ClaudeCodeReviewSend*
:ClaudeCodeReviewSend   Send every note to Claude in one message
                        (|claudecode-notes|), as `cR` does.

                                                            *:ClaudeCode-run*
:ClaudeCode run [{account}] [{args}]
                        Run Claude as a cswap account and keep it for later
                        launches (|claudecode-cswap|). Other arguments of
                        `:ClaudeCode` go to Claude as before.

                                                              *:ClaudeCodeZen*
:ClaudeCodeZen [{args}] Toggle zen (|claudecode-zen|). {args} go to the
                        `claude` command when zen has to start Claude, as in
                        `:ClaudeCodeZen --resume`. They do nothing when
                        Claude already runs. Defined when `zen.enabled` is
                        true.

==============================================================================
OPTIONS                                                   *claudecode-options*

The options go into the same table as upstream's, passed to
`require("claudecode").setup()`. Three keys are new: `review`, `zen` and
`cswap`.
A wrong type or an unknown key in `review.keymaps` makes `setup()` fail with
a message that names the option. Defaults:
>lua
    require("claudecode").setup({
      review = {
        enabled = true,
        before_write = true,
        keymaps = {
          keep = "cs", revert = "cx", keep_all = "cS", revert_all = "cX",
          next = "]k", prev = "[k", last = "]K", first = "[K",
          note = "cr", note_range = "<leader>an",
        },
        notes = {
          enabled = true,
          send = "batch",
          advance = true,
          send_keymap = "cR",
          list_keymap = "<leader>an",
        },
        files_keymap = "<leader>ak",
        advance = "hunk",
        cross_files = true,
        hint = true,
        word_diff = true,
        picker = "auto",
      },
      zen = {
        enabled = true,
        keymap = "<M-z>",
      },
      cswap = {
        cmd = "cswap",
      },
    })
<
The `review` table is described under |claudecode-review|, the `zen` table
under |claudecode-zen|, the `cswap` table under |claudecode-cswap|.

review.enabled                                     *claudecode-review.enabled*
    Type: boolean. Default: `true`.
    Turns hunk review on. With `false` no hooks are attached, and the review
    keys, |:ClaudeCodeReview| and review before write are gone.

review.before_write                           *claudecode-review.before_write*
    Type: boolean. Default: `true`.
    Review Manual-mode proposals with the same engine
    (|claudecode-review-before-write|). The plugin sets `diff_opts.provider`
    unless you did. With `false` upstream's diff views stay, and Manual mode
    no longer asks about edits your settings allow (|claudecode-modes|).

review.keymaps                                     *claudecode-review.keymaps*
    Type: table. The keys below. Each is a key string or `false`, which
    leaves the action unmapped. A name that is not below makes `setup()` fail.
    Buffer-local while a file is under review (|claudecode-review-keys|).

review.keymaps.keep                           *claudecode-review.keymaps.keep*
    Type: string or false. Default: `"cs"`.
    Keep the hunk under the cursor.

review.keymaps.revert                       *claudecode-review.keymaps.revert*
    Type: string or false. Default: `"cx"`.
    Revert the hunk under the cursor and write the file.

review.keymaps.keep_all                   *claudecode-review.keymaps.keep_all*
    Type: string or false. Default: `"cS"`.
    Keep every hunk in the buffer.

review.keymaps.revert_all               *claudecode-review.keymaps.revert_all*
    Type: string or false. Default: `"cX"`.
    Revert every hunk in the buffer.

review.keymaps.next                           *claudecode-review.keymaps.next*
    Type: string or false. Default: `"]k"`.
    Jump to the next hunk. Takes a count.

review.keymaps.prev                           *claudecode-review.keymaps.prev*
    Type: string or false. Default: `"[k"`.
    Jump to the previous hunk. Takes a count.

review.keymaps.last                           *claudecode-review.keymaps.last*
    Type: string or false. Default: `"]K"`.
    Jump to the last hunk.

review.keymaps.first                         *claudecode-review.keymaps.first*
    Type: string or false. Default: `"[K"`.
    Jump to the first hunk.

review.keymaps.note                           *claudecode-review.keymaps.note*
    Type: string or false. Default: `"cr"`.
    Open a note for Claude on the line under the cursor
    (|claudecode-notes|).

review.keymaps.note_range               *claudecode-review.keymaps.note_range*
    Type: string or false. Default: `"<leader>an"`.
    Visual mode: open a note on the selected lines. Not on `c`: in Visual
    mode `c` acts at once, and a mapping on it would make it wait.

review.notes                                         *claudecode-review.notes*
    Type: table. Notes for Claude (|claudecode-notes|).

review.notes.enabled                         *claudecode-review.notes.enabled*
    Type: boolean. Default: `true`.
    `false` maps neither the note keys nor the send and list keys, and
    leaves |:ClaudeCodeReviewNotes| undefined.

review.notes.send                               *claudecode-review.notes.send*
    Type: string. Default: `"batch"`.
    "batch": <CR> saves a note and <S-CR> sends every note. "enter": <CR>
    sends at once.

review.notes.advance                         *claudecode-review.notes.advance*
    Type: boolean. Default: `true`.
    A note counts as a decision on its hunk for |claudecode-review.advance|.

review.notes.send_keymap                 *claudecode-review.notes.send_keymap*
    Type: string or false. Default: `"cR"`.
    Global normal-mode key that sends every note. Neovim waits for a motion
    after `c` anyway, and `R` is none, so it delays nothing.

review.notes.list_keymap                 *claudecode-review.notes.list_keymap*
    Type: string or false. Default: `"<leader>an"`.
    Global normal-mode key for |:ClaudeCodeReviewNotes|. In Visual mode the
    same key leaves a note on the selection
    (|claudecode-review.keymaps.note_range|).

review.files_keymap                           *claudecode-review.files_keymap*
    Type: string or false. Default: `"<leader>ak"`.
    Global normal-mode key for |:ClaudeCodeReview|. `false` leaves it
    unmapped. Zen shows the key next to its counter.

review.advance                                     *claudecode-review.advance*
    Type: string or false. Default: `"hunk"`.
    Where the cursor goes after `cs` or `cx`. "hunk": to the next hunk, or
    to the first one after the last; once the file has none left, it stays.
    "file": the same, and once the file is done, by its last hunk or by `cS`
    or `cX`, the next file waiting for review opens at its first hunk.
    `false`: the cursor stays where it is.

review.cross_files                             *claudecode-review.cross_files*
    Type: boolean. Default: `true`.
    `]k` past the last hunk opens the next file waiting for review at its
    first hunk, and `[k` before the first hunk the previous file at its last
    hunk. The list goes in path order and wraps around. `false` keeps them
    inside the file.

review.hint                                           *claudecode-review.hint*
    Type: boolean or string. Default: `true`.
    The hint at the hunk under the cursor. `true` builds it from your keys,
    "cs keep · cx revert" with the defaults. A string replaces it, `false`
    hides it. The number of the hunk, "2/5", comes before it either way and
    goes with it.

review.word_diff                                 *claudecode-review.word_diff*
    Type: boolean. Default: `true`.
    Highlight only the changed words inside changed lines.

review.picker                                       *claudecode-review.picker*
    Type: string. Default: `"auto"`.
    Which list shows the files waiting for review: "snacks", "fzf" (fzf-lua)
    or "select" (`vim.ui.select`). "auto" takes the first one it finds, in
    that order.

zen.enabled                                           *claudecode-zen.enabled*
    Type: boolean. Default: `true`.
    Turns zen on. With `false` |:ClaudeCodeZen| and the zen key do not exist.

zen.keymap                                             *claudecode-zen.keymap*
    Type: string or false. Default: `"<M-z>"`.
    Toggles zen in normal mode and inside the Claude terminal. `false`
    leaves it unmapped; |:ClaudeCodeZen| still works.

cswap.cmd                                               *claudecode-cswap.cmd*
    Type: string. Default: `"cswap"`.
    The cswap executable for |:ClaudeCode-run|: a name on your PATH or a
    full path.

DIFF PROVIDER                                       *claudecode-diff-provider*

`diff_opts.provider` takes over the `openDiff` call from the built-in native
and unified views. Review before write is one such provider; yours replaces
it.
>lua
    require("claudecode").setup({
      diff_opts = {
        provider = {
          open = function(ctx)
            -- Show ctx.new_file_contents against ctx.old_file_path, then
            -- answer Claude once:
            --   ctx.accept(text)  Claude writes `text` to the file
            --   ctx.reject()      the file stays as it is
          end,
          close = function(ctx, reason)
            -- Remove your UI.
          end,
          reject_command = function(ctx) -- optional
            ctx.reject()
          end,
        },
      },
    })
<
`open` and `close` are required. `reject_command` tears your UI down when
Claude gives up on the proposal before you answered.

`ctx` has these fields:
    tab_name           string   name of the diff, unique per proposal
    old_file_path      string   the file as it is now
    new_file_path      string   where Claude will write
    new_file_contents  string   Claude's proposed text
    is_new_file        boolean  the file does not exist yet
    tool               string?  Claude's tool, "Edit" or "Write", when known
    accept(content)    Claude writes `content` to the file
    reject()           the file stays as it is

How it behaves:

- Claude waits until you call `accept` or `reject`. Only the first call
  counts.
- The plugin calls `reject_command` when Claude closes the tab, when the
  Claude session disconnects and when a new diff reuses the tab name. Claude
  gets a rejection once the handler returns, even if the handler never
  called `reject`.
- `accept` may pass text that differs from Claude's proposal. Claude writes
  your text, but learns only that "the user modified your proposed content",
  not what you changed.
- `close` runs once per diff: after Claude closes the tab, when the session
  disconnects, when a new diff reuses the tab name, and when `open` throws
  (`reason` is "setup failed"). Make it safe to run on a half-built UI.
- A provider gets the diff even when the file's buffer has unsaved edits. The
  built-in views refuse it.
- Claude Code (checked on 2.1.304) treats the answer by tool. An Edit of an
  existing file becomes a patch against it and lands byte for byte. The text
  of a Write, or of any new file, loses one trailing newline, so `accept`
  adds one, and the file ends up with exactly your text. openDiff does not
  name the tool: the review hooks note it before Claude asks. Without their
  note (Claude started outside Neovim) an existing file's text goes as is, as
  in upstream's views.

The plugin fires the User events ClaudeCodeDiffOpened and ClaudeCodeDiffClosed
for provider diffs too (|claudecode-events|).

HEALTH CHECK                                               *claudecode-health*

>vim
    :checkhealth claudecode
<
The report opens with the IDE connection: the Claude CLI, the terminal
provider, the WebSocket server and the lock file. Sections for hunk review,
zen and accounts follow and report:

- whether Neovim is 0.11 or newer;
- whether the review hooks are attached, and where their settings file is;
- whether `git` is installed and Neovim has a server address;
- how many files wait for review, where the state directory is, whether other
  users can read it, and the last errors in `hooks.log`;
- which list shows the files (|claudecode-review-files|);
- whether zen can work with your `terminal.provider` (|claudecode-zen|);
- whether `:ClaudeCode run` finds cswap (|claudecode-cswap|).
